Product Case Study — 2025

FollowUp AI

An internal B2B CRM built from scratch — pipeline management, AI-powered email analysis, and Outlook integration — for a food import and distribution company.

Stack

Node.js · Supabase · Claude API · Whisper · Microsoft Graph

Status

Active development at Confluencia

Role

Sole designer & developer

The Problem

Confluencia, a B2B food import and distribution company, had no centralized system to manage client relationships. 100+ active business contacts were scattered across tools, emails were buried in OneDrive folders inaccessible to any intelligent system, follow-ups were consistently missed, and the sales pipeline had no visibility.

The team had no shared task management and no single place where everything lived together.

My Role

I identified the problem myself — nobody asked me to build this. I noticed the disorganization firsthand and decided to design and lead the development of an internal CRM from scratch.

Why Not HubSpot?

Before building, we evaluated existing CRMs including HubSpot. It wasn't the right fit — the base plan lacked key features we needed (automated follow-up alerts via Outlook calendar), while higher tiers included extensive functionality we would never use.

For a small B2B team, we needed something leaner and more specific. Building internally was the more efficient and cost-effective choice.

What I Built

  • Contact & pipeline management Centralized tracking of 100+ B2B contacts with sales stage visibility
  • Outlook integration via Microsoft Azure Connecting emails to the CRM so Claude AI can read, analyze, and extract insights from client conversations
  • AI-powered email analysis Understanding where each deal stands based on email content
  • Whisper integration Transcribing and processing voice messages
  • Smart alerts Automated reminders via email and Outlook calendar when a contact hasn't responded
  • Task manager Assignable tasks for both admin and team members
  • Dual interface Optimized for both desktop and mobile use

Key Decisions

Prioritized simplicity for non-technical users while building powerful AI features underneath. Scoped the product tightly — only what the team would actually use. Chose Supabase for the database, Node.js for the backend, and Claude API for the intelligence layer.

What I Learned

Azure/Microsoft Graph integration, UX structure for internal tools, how to scope an AI product around real business constraints, and how to evaluate build vs. buy decisions.
